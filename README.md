# Business Entity Resolution — Combined Pipeline

End-to-end pipeline that runs raw TSV ingestion, normalization, and
entity-resolution matching in a single command.

```
python run_pipeline.py
```

---

## 1. What the Pipeline Does

This repository combines two previously separate systems:

| Stage | Name | Description |
|---|---|---|
| Stage 1 | **Preprocessing** (MLnNor) | Ingests raw TSVs → validates schema + entity IDs → normalizes text (Unicode, case, whitespace, abbreviations, legal suffixes) → canonicalizes names and addresses → extracts landmarks, numbers, postal codes, script class → writes cleaned TSVs + data-quality report |
| Bridge | **Contract converter** | Transforms MLnNor's rich multi-column output into the exact two-file format (clean_text + feature) expected by the matching pipeline |
| Stage 2 | **Matching** (MLnAWS) | Multi-channel blocking (TF-IDF + BM25 + Exact Match + FAISS) → feature engineering → LightGBM training with hard-negative mining → threshold sweep → final entity-resolution output |

```
dataset/raw/
  train/{train_source1,2,3}.tsv + train_ground_truth.tsv
  test/{test_source1,2,3}.tsv
        │
        ▼  Stage 1 – MLnNor preprocessing
output/preprocessing/processed/
  {train,test}/source{1,2,3}_clean.tsv
  train/ground_truth_clean.tsv
        │
        ▼  Bridge – contract conversion
dataset/real/
  clean_s1_{train,test}.tsv
  clean_s2s3_{train,test}.tsv
  feature_s1_{train,test}.tsv
  feature_s2s3_{train,test}.tsv
  ground_truth_train.tsv
        │
        ▼  Stage 2 – MLnAWS entity resolution
output/matching/
  matching_results.tsv        ← final output: upload to leaderboard
  candidate_pairs.tsv         ← include in submission zip
output/pipeline_report.json   ← machine-readable run summary
```

## 9. What Happens Internally

### Stage 1 — Preprocessing (MLnNor)

For each raw source file:
1. Reads TSV with `dtype=str, keep_default_na=False` (no silent NA coercion)
2. Validates schema and entity ID format
3. Applies Unicode NFKC normalization
4. Lowercases and collapses whitespace
5. Strips decorative leading characters
6. Canonicalizes business names (legal suffix mapping: `pvt→private`, `ltd→limited`, `&→and`, etc.)
7. Canonicalizes addresses (abbreviation mapping: `rd→road`, `st→street`, etc.)
8. Extracts: landmark phrases, digit sequences, postal codes, sorted tokens
9. Classifies name script (latin, devanagari, tamil, etc.)
10. Enforces row-count invariant (no rows dropped or added)
11. Enforces ID-set invariant (entity IDs preserved exactly)
12. Writes collision diagnostics (never removes records)
13. Writes `preprocessing_report.json`

### Bridge Layer

Converts MLnNor's rich 16-column output to MLnAWS's two-file format:
- `clean_text` = `business_name_normalized + " " + business_address_normalized`
- `clean_name` = `business_name_normalized`
- `clean_address` = `business_address_normalized`
- `clean_country` = `country_normalized`
- Combines S2 + S3 into one corpus
- Renames `matched_entity_ids` → `matching_entity_ids` (MLnAWS's canonical name)

All streaming — never loads a 2.5 GB file fully into memory.

### Stage 2 — Matching (MLnAWS)

1. Fits multi-view TF-IDF vectorizers on S2+S3 corpus
2. Multi-channel blocking: Exact Match + Multi-View TF-IDF + FAISS (if available) + BM25
3. Fuses candidate lists
4. Measures blocking recall against ground truth
5. Builds pair feature table (13 features: name similarity, address similarity, metadata, retrieval agreement)
6. Hard-negative mining: lexical, address, retrieval, and random negatives
7. Entity-level train/validation split (15% holdout by entity, not by pair)
8. LightGBM training with hard-negative mining (HNM)
9. Threshold sweep over validation set (F0.5 metric)
10. Test inference
11. Post-processing: dedup, filter invalid IDs, full coverage check
12. Candidate consistency check
13. Writes final output files

## 12. How to Resume

The pipeline uses checkpoints. If it stops midway, re-run:

```bash
python run_pipeline.py
```

It automatically skips completed stages. To see checkpoint state:

```python
from pipeline_checkpoints import CheckpointStore
from pipeline_config import REPO_ROOT
store = CheckpointStore(REPO_ROOT / "checkpoints")
print(store.resume_summary())
```

To force a full re-run from scratch:

```bash
python run_pipeline.py --force
```

To re-run only from a specific stage, delete its sentinel file:

```bash
# Example: re-run matching but not preprocessing
rm checkpoints/stage_4a_vectorizer_fitted
rm checkpoints/stage_4b_matching_train_done
rm checkpoints/stage_4c_matching_complete
rm checkpoints/stage_5_final_outputs_validated
python run_pipeline.py --skip-preprocessing
```

## 17. Common Errors

| Error | Cause | Fix |
|---|---|---|
| `raw validation: missing dataset/raw/train/train_source1.tsv` | Raw files not placed yet | Copy raw TSV files to `dataset/raw/train/` and `dataset/raw/test/` |
| `schema mismatch for train/source1` | Wrong column names in raw file | Verify TSV has `entity_id, business_name, business_address, country` |
| `Required packages not installed` | Missing pip packages | Run `pip install -r requirements.txt` |
| `ERROR: Prepared data files missing` | Running matching without preprocessing | Run without `--skip-preprocessing` first |
| `MemoryError` during BM25 | Not enough RAM for BM25 on large corpus | Add `--skip-bm25` flag |
| `Candidate consistency check failed` | Blocking/inference mismatch | Delete matching checkpoints and re-run |
| Pipeline interrupted (Ctrl+C) | User interrupt | Re-run — checkpoints are saved |

## 18. Memory Considerations

The pipeline on a 128 GB RAM / 2.5 GB dataset machine:

| Stage | Peak RAM |
|---|---|
| Preprocessing (per split, per source) | ~2–5 GB |
| Bridge (streaming, 100k-row chunks) | ~0.5 GB |
| TF-IDF vectorizer fitting | ~4–8 GB |
| BM25 blocking | ~8–12 GB |
| Feature engineering | ~5–10 GB |
| LightGBM training | ~4–8 GB |

To reduce memory usage:
- Use `--skip-bm25` to save ~8–12 GB
- Use `--chunk-size 50000` for smaller preprocessing chunks (default: 100000)
- Use `--top-k 30` for fewer blocking candidates (reduces feature table size)

## 19. CPU/Threading Configuration

The pipeline sets these environment variables automatically before importing
numpy/LightGBM to prevent CPU oversubscription:

```
OMP_NUM_THREADS    = floor(16 / workers)   (capped at 4)
MKL_NUM_THREADS    = (same)
OPENBLAS_NUM_THREADS = (same)
NUMEXPR_NUM_THREADS  = (same)
```

For a 16-vCPU machine with `--workers 8` (the default):
- Each worker process gets 2 BLAS/OpenMP threads
- LightGBM uses `--workers` threads for training

To tune:
```bash
python run_pipeline.py --workers 4    # fewer, more threads each
python run_pipeline.py --workers 16   # maximum parallelism
```

## GCP RUN PROCEDURE

Copy-paste these commands on the GCP VM:

```bash
# 1. Upload raw data from local laptop (run on your LOCAL machine)
#    Replace GCP_IP and /path/to/raw with your actual values
# gcloud compute scp --recurse /path/to/raw/train/ user@instance:~/combined-pipeline/dataset/raw/train/
# gcloud compute scp --recurse /path/to/raw/test/  user@instance:~/combined-pipeline/dataset/raw/test/

# 2. SSH into GCP VM
# gcloud compute ssh user@instance

# 3. Clone and set up (on the VM)
git clone <repository-url>
cd combined-pipeline

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 4. Verify raw data placement
ls dataset/raw/train/
ls dataset/raw/test/

#   train_source1.tsv  train_source2.tsv  train_source3.tsv  train_ground_truth.tsv
#   test_source1.tsv   test_source2.tsv   test_source3.tsv

# 5. Dry run — validates data without processing

# 6. Run the complete pipeline (recommended: use nohup or screen/tmux)
nohup python run_pipeline.py --workers 8 > nohup.out 2>&1 &
echo "Pipeline started, PID=$!"

# 7. Monitor progress
tail -f logs/pipeline_*.log

# 8. Check checkpoint state after any interruption
python -c "
from pipeline_checkpoints import CheckpointStore
from pipeline_config import REPO_ROOT
store = CheckpointStore(REPO_ROOT / 'checkpoints')
print(store.resume_summary())
"

# 9. Resume if interrupted
python run_pipeline.py --workers 8

# 10. Optional: disable BM25 to save ~10 GB RAM
python run_pipeline.py --workers 8 --skip-bm25

# 11. Verify outputs
ls -lh output/matching/

# 12. Run tests (optional, uses only synthetic fixtures)

```
